# ZURI notifications — system and interface

## Product contract
One inbox, accessible from the header bell in Lounge and all four worlds and from Profile. A badge counts unread, unarchived, unsnoozed, unmuted items; merely opening the inbox does not mark everything read. Opening an item marks it read and uses canonical app navigation, preserving the existing return path. Inbox, Unread, Attention, Snoozed and Archive views filter by world. Read/unread, one-hour snooze, archive/restore and archive undo are local persistent actions. No destructive bulk delete. Cards retain source-world identity, concise body and readable time. Preferences use explicit controls with accessible names, keyboard focus and reduced-motion transitions.

## Working on-device implementation
New tasks, chapters and Ping joins create honest local confirmations, never fabricated incoming activity. Explicit due dates on incomplete tasks derive Attention reminders while the app is open. There is no inference of deadlines from prose. Snooze expiration is checked while the centre is open and on subsequent renders. Completing/removing a task removes its derived reminder; original action history remains historical. The inbox is synchronous local data and has no artificial network loading animation. Empty views explain why they are empty. Existing app storage-error/offline banners handle persistence failure; the app must not claim cloud delivery. Up to 1,000 action records are retained; exceeding the limit drops the oldest action records, without deleting the underlying object. Muted categories retain history but leave the active inbox. Archive does not delete source objects. Backups validate records, merge history by stable ID and keep current-device preferences and controls.

## Preferences and attention policy
Categories: reminders, personal activity, messages, communities, updates and security. Messages/community/updates are delivery-ready preferences only, pending authoritative events. No unsolicited promotional seed activity. Space Echo consent remains separate; a global category preference must never opt a person into a Space's updates. Quiet hours use Africa/Kampala, including overnight ranges; equal endpoints mean all day. Quiet hours pause future interruptions, not inbox visibility. Message previews default off for future device alerts. The prototype does not request browser notification permission, send push/email, emit sound or schedule background reminders. No claim of OS delivery is made. Security alerts remain separate from optional marketing; account verification and production security delivery are pending.

## Production event contract — pending backend
Use an authenticated, append-only domain outbox, not frontend toasts or model text. Event envelope: event ID, recipient ID, actor ID, source object kind/ID, source version, event kind, occurrence timestamp, category, sensitivity and allowed CTA. Enforce recipient access, block/mute state, membership and publication permissions before fanout AND on fetch/open. Do not include private message body in push payloads by default. A revoked or deleted source resolves to an unavailable state without leaking its content.

In-app record ID is unique per recipient + domain event, providing idempotency. Repeated replies can group by source and bounded time window; preserve individual event IDs and unread counts. Never group security with promotions. Respect self-action suppression for incoming social alerts. Scheduled reminder jobs require explicit dates/time zones and cancel/reschedule against source revisions. Digest batches are opt-in and honor quiet hours; important is a user-selected classification, not a fabricated urgency score. No surveillance-derived attention ranking or automatic neglect deletion.

Delivery adapters: in-app first, then explicit device-push and separately consented email. Evaluate consent, recipient authorization, per-source mute, per-category settings, quiet hours and rate limits before enqueueing. Use a deduplicated queue, expiring payloads, exponential retry for transient failures, dead-letter review and invalid-token revocation. Track queued/provider-accepted/failed separately; provider acceptance is not read or confirmed delivery. Read state sync is per authenticated recipient; never mark a conversation read just because a notification was viewed. Tokens and destinations are server-only and account scoped. No credentials or private content in logs.

## Launch gates and acceptance
Pending: database schema/RLS, outbox producers for chats/topics/mentions/invitations/attendance/offerings, delivery worker, cross-device sync, device token lifecycle, permission UI after explicit opt-in, rate limits, abuse controls, digests, per-thread mute overrides, source-access rechecks, retention/deletion policy and observability.
